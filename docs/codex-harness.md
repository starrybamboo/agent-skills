# Codex harness

Codex consumes the same pinned pstack source as the Claude Code plugin. The
repository generates its adapter and explicit Skill entries instead of copying
Cursor tools into Codex without translation.

## Artifacts

- `harness/codex/adapter/` is the maintained Codex adapter: router Skill, tool
  mapping, subagent briefs, and source resolver.
- `harness/codex/skills/` is generated from `plugins/pstack/skills/`.
- `harness/codex/state.json` records the pstack version, upstream revision, and
  generated Skill names.

The adapter maps:

- Claude/Cursor `Task` and `Agent` to Codex `spawn_agent`.
- Structured questions to plain-text product decisions.
- Todo tools to a visible checklist.
- Skill calls to direct reads of the pinned `SKILL.md`.
- Claude, Grok, and other host-specific model slugs to parent-model inheritance
  unless the user explicitly configures a Codex override.

## Update path

```text
cursor/plugins
  -> upstreams.lock.json
  -> plugins/pstack
  -> harness/codex
  -> $CODEX_HOME/pstack-codex/upstream
  -> $CODEX_HOME/skills
```

One upstream synchronization updates the lock, vendored plugin, Claude
metadata, and Codex harness. The generated harness is checked by `npm test`.
Local installation remains explicit.

## Commands

```bash
npm run codex:sync
npm run codex:check
npm run codex:install
npm run codex:status
```

`codex:install` refuses to overwrite a Skill directory that was not generated by
this harness. It writes the managed payload and installation state under
`$CODEX_HOME/pstack-codex/`. The default `CODEX_HOME` is `~/.codex`.

## Host limits

The harness does not provide Cursor Automations, webhooks, routine wakes,
Bugbot, Cursor cloud agents, Claude live artifacts, or automatic Claude model
routing. A task reports these as skipped rather than marking them complete.
